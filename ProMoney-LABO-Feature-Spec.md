# ProMoney LA-BO — Feature Spec (Suman's list + Munna's additions)

Set 2026-11-13. Engine: **Meta Model API** (chat + vision), Groq fallback.
Every feature obeys the Constitution v2: numbers only from the engine
(financeMath); LA-BO proposes, the user confirms, only then it saves
(K2); replies in the user's language (K4); AI output numbers verified
against engine output (Q1).

## Suman's four (the core promise)

- **F1. Chat add** ✅ *built (v1).* Type "spent 500 on coffee" → parse →
  confirm card → save. Works EN / Roman Nepali / Japanese.
- **F2. Voice communication.** Speak to LA-BO and **LA-BO speaks back.**
  - In: Web Speech API recognition (EN/JA), text lands in the input for
    a quick look before sending.
  - Out: browser speech synthesis reads LA-BO's reply aloud (same
    language as the reply). A speaker toggle mutes it — voice out is
    never forced.
  - Hands-free flow: mic → speak → auto-send after a pause → spoken
    reply → for any add, LA-BO *says* the proposal and the user taps
    "Add it" (voice alone never saves — K2).
- **F3. Bill photo.** Camera/upload a bill or receipt photo → Meta
  vision reads shop, date, total (and items if printed) → confirm card
  pre-filled → user checks → save. Blurry/failed read → LA-BO says so
  and offers manual entry; it never guesses a total.
- **F4. Chat file import (CSV / PDF).** Drop a bank/e-money statement
  file **into the chat** → LA-BO extracts the records → shows a
  **review list** (each row: date, name, amount, category guess, tick
  box) with the total → user unticks wrong rows → "Add selected" saves.
  - CSV: parsed by deterministic backend code (no AI maths); AI only
    helps map unknown column layouts.
  - PDF: extracted via Meta API (vision/text); rows the extractor is
    unsure about are flagged ⚠️ in the review list.
  - Duplicates: rows matching an existing record (same date + amount +
    name) are pre-unticked and marked "looks like a duplicate".

## Munna's additions (best for this app)

- **F5. Multi-add in one message.** "Khana 800, bus 220, coffee 500"
  → three proposals on one confirm list, saved together.
- **F6. Undo.** After any LA-BO save, an **Undo** button sits on the
  result ("Added ¥500 Food — Undo"). One tap removes exactly those
  records. LA-BO also understands "undo that" in chat.
- **F7. Custom reports from chat** *(expanded by Suman, 2026-11-13).*
  The user describes the report they want in plain words — period,
  categories, accounts, summary or detail, chart and/or table:
  "October, Food and Transport only, with a chart." LA-BO first
  **reads back what it understood** ("October · Food + Transport ·
  chart + table — shall I build it?") and builds only after a yes,
  because a report is defined by words and a wrong guess wastes the
  user's time. Outputs, all generated by app code from engine figures
  (J5 — the AI interprets the request, it never calculates):
  1. **In-chat report card** — the summary rendered inside the chat,
     responsive: one clean column on a phone, wide with chart beside
     table on desktop.
  2. **PDF download** — clean A4 layout, big readable numbers,
     single-column flow so it stays easy to read when opened on a
     phone; header shows period, scope and "figures by ProMoney
     engine".
  3. **CSV download** — for Excel/Sheets, same figures.
  4. **Image (PNG)** — the report card rendered as one clean picture,
     for sharing on LINE/Messenger or saving to the phone gallery.
  **Format rule:** LA-BO gives the format the user **asked for** —
  "PDF ma deu" → PDF, "CSV" → CSV, "photo banaideu" → image. If the
  user asks for nothing, the default is the in-chat card + a PDF link.
  Every format shows the SAME engine numbers; if they ever differ,
  that is a bug, not a choice.
- **F8. Engine alerts, spoken by LA-BO.** When the engine fires an
  alert (G5: category over pace, safe-to-spend negative, bill due in
  3 days), LA-BO opens with it in chat — e.g. "Rent is due in 3 days,
  and Food is a bit fast this month." Numbers still 100% engine.

## Simulators & Loans (added 2026-11-13, Suman's ideas)

The pattern for all of these: **the engine simulates, the AI explains.**
A simulation NEVER saves or changes real data — screens and chat label
it SIMULATION. Rates and terms are user-entered; the engine never
invents bank terms.

- **F9. Check Before You Buy.** "Can I buy ¥40,000 shoes?" → the
  engine recomputes the month *as if bought*: safe-to-spend per day
  after, the category's pace, the nearest goal's date slip. LA-BO
  answers in plain words with the three numbers: fine / tight / will
  break the month — and what would make it fine (e.g. "after the 25th
  payday it fits"). Nothing is recorded unless the user later buys
  and adds it for real.
- **F10. What Can I Do With My Money?** Uses the month's surplus
  (H4): the engine ranks safe options with numbers — top up the
  bills-safety buffer, extra loan payment (interest it would save),
  goal boost (days it pulls the date closer). The user picks one →
  LA-BO prepares that transfer/contribution → confirm card (K2).
  Educational simulation, labelled as such — never personalised
  investment advice.
- **F11. What-If Simulator.** Change one thing — "baito ¥20,000 less
  next month", "rent up ¥5,000", "one extra ¥10,000 loan payment" —
  and see the month, the goals and the debt-free date move. A sandbox:
  sliders/inputs on a simulator screen, and the same questions work
  in LA-BO chat.
- **F12. Loans page — breakdown + fastest payoff.** A dedicated page
  under **My Plans ▸ Loans** (nav amendment to P5, Suman's call):
  - Per debt: borrowed, paid so far, remaining, interest paid so far,
    monthly payment, payoff date at current pace.
  - Totals: total owed, total monthly debt payment, **debt-free
    date**.
  - **Payoff planner** with the two proven strategies side by side:
    **Avalanche** (highest interest rate first — least total
    interest) and **Snowball** (smallest balance first — fastest
    first win). Plus an extra-payment slider: "+¥5,000/month → debt
    free 7 months sooner, ¥38,000 interest saved" — all engine
    maths (monthly interest = balance × rate ÷ 12; standard
    amortisation), AI only narrates the comparison.
  - Slim scope only: breakdown + simulation. Full banking
    amortisation products stay parked (Constitution Part III).

## Home Screen Specification (Layer 2) — set 2026-11-13 by Suman

Mobile-first, top to bottom. Every number is the engine's; tapping any
card opens its breakdown (Constitution P2 — proof on demand).

1. **Money you hold** — big card: spendable balance (Cash + Bank +
   prepaid Digital, G2). Small lines under it: **Your real money**
   (net worth, D1) and **To pay back** (total liabilities, B2).
2. **Safe to spend today** — ¥X/day (G4) with the month's
   safe-to-spend beside it; breakdown shows the formula line
   (income − bills still due − goal plan) ÷ days left.
3. **Bills to pay** — next bills with name, amount and "due in N
   days"; anything **overdue is pinned on top in red**; footer shows
   total still due this month.
4. **Warnings strip** — engine alerts (G5), ranked: overdue bill →
   safe-to-spend negative → budget running out → over pace → goal
   slipping. Example in the user's words: **"Groceries: only 18% of
   the budget is left"** — fired when a category's remaining budget
   falls to the user's set threshold.
5. **Goals row** — progress rings (Money-Pro-style circles) for the
   top goals; a ¥0 target shows "Set a target", never a fake %
   (Constitution H3).
6. **Recent transactions** — latest 5 **with their title/note shown**
   (fixes the "Category · —" empty look seen 2026-11-13).
7. **LA-BO line** — the top alert in LA-BO's words + a quick-ask box
   into chat (F8).

### Set-once settings (Settings page — set one time, engine remembers)

Stored in the database per user (needs Constitution Step 2c — settings
must survive restart):

- **Budget warning threshold:** warn when a category's remaining
  budget ≤ **20%** (default; user can change).
- **Minimum buffer:** ¥ kept untouchable in safe-to-spend (default ¥0).
- **Bill reminder window:** warn **3 days** before a due date
  (default; user can change).
- **Payday:** day of the month income usually arrives (e.g. 25th) —
  powers "income still expected" in safe-to-spend.
- **Expected monthly income:** optional ¥; if unset, the engine uses
  recorded income only and says so.
- **Per credit card:** closing day + payment day (set once per card)
  — powers card-bill due warnings.
- **Warning switches:** which warnings Home shows (budget / pace /
  bills / goals) — each on by default.

Defaults are chosen so Home is fully useful **before** the user sets
anything; every set-once value only sharpens the numbers.
